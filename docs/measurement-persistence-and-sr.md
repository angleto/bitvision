# Measurement persistence and DICOM SR export

The 2D viewer lets users draw distance, angle, and area measurements on
series. Before this change the measurements lived only in React state
and were lost on reload. This document describes how they are now
persisted and exported as a DICOM Structured Report (SR).

## Storage model

Measurements reuse the existing `annotations` table
(`backend/src/bvphoenix/db/models/annotations.py`) instead of a new
schema. Reusing that table gives us author tracking, audit timestamps,
the `source = human|llm` distinction and permission plumbing for free.

| column | value for a measurement |
|--------|-------------------------|
| `target_kind` | `"series"` |
| `target_id`   | series UUID |
| `kind`        | `"measurement"` |
| `source`      | `"human"` |
| `author_subject_id` | current user |
| `payload` (JSONB) | shape below |

`payload` shape:

```json
{
  "tool": "distance" | "angle" | "area",
  "points": [{"x": 12.3, "y": 45.6}, ...],
  "value": 38.2,
  "unit": "mm" | "deg" | "mm2",
  "label": "optional",
  "slice_index": 34,
  "viewport": "axial" | "sagittal" | "coronal",
  "client_id": "m17"
}
```

`client_id` is an opaque string generated by the frontend. It is the
key the upsert endpoint uses to match an incoming measurement against
an existing row, so a debounced sync doesn't create duplicates on every
keystroke.

## REST surface

All endpoints live in `backend/src/bvphoenix/api/measurements.py`.

- `GET /api/series/{id}/measurements`
  Lists all measurement rows for a series. Permission:
  `read:annotations` on the parent study.

- `POST /api/series/{id}/measurements`
  Body: `{ measurements: MeasurementIn[], replace?: bool }`.
  Upserts each measurement keyed on `payload.client_id`. When
  `replace = true` the server also deletes any rows whose `client_id`
  is absent from the payload — this is what the frontend hook uses for
  a full sync. Permission: `write:annotations`.

- `DELETE /api/measurements/{id}`
  Removes a single row. The author of the measurement can always
  delete their own; otherwise `write:annotations` is required.

- `GET /api/series/{id}/measurements.sr`
  Returns the DICOM-SR-shaped JSON described below.

## DICOM SR export

`backend/src/bvphoenix/services/dicom_sr_export.py` serialises a list
of measurements into a JSON document whose shape follows DICOM
Structured Report TID 1500 *Measurement Report* (PS3.16) and the IHE
Radiology SR Content Profiles. Producing a valid DICOM Part 10 binary
requires `highdicom` or `pydicom` and substantial template wiring — out
of scope for this iteration — but every leaf in the JSON tree carries
the coded concepts and UCUM units a downstream writer needs. Concretely:

- `distance` -> DCM 121206 "Distance", unit `mm`
- `angle`    -> DCM 121211 "Angle", unit `deg`
- `area`     -> SCT 42789003 "Area", unit `mm2`

Each measurement becomes a `CONTAINER` content item with a
`TrackingIdentifier` (DCM 112039), a numeric result (`NUM`), an
optional `TEXT` finding note, and an `SCOORD` referencing the polyline
/ polygon used to draw it. The top-level container is
`ImagingMeasurements` (DCM 126010) per TID 1500.

The JSON output is safe to pipe into a future `highdicom` writer or to
display in a human-readable viewer without further transformation.

## Frontend hook

`frontend/src/lib/measurementPersistence.ts` exposes
`useMeasurementPersistence(seriesId, measurements, options)`:

1. On mount it calls `GET /measurements` and returns rows via
   `options.onLoad`. Callers merge these into their local state.
2. Every time the `measurements` reference changes it schedules a
   debounced `POST` (default 800 ms) with `replace: true`, so deletes
   propagate as well as inserts.
3. `exportSr()` flushes pending writes then calls
   `GET /measurements.sr` and returns the JSON document.
4. `flush()` forces an immediate save — useful on navigation / unmount.

The hook is SSR-safe; it no-ops when `enabled` is false so the viewer
can gate persistence on authenticated users.

## Future work

- Swap the JSON SR for a real DICOM Part 10 binary via `highdicom`,
  exposing `GET /measurements.dcm`.
- Encode `slice_index` + `viewport` as proper `SourceImageForSegmentation`
  references once per-slice SOP Instance UIDs are tracked.
- RLS policy for the `annotations` table (see `docs/authorization.md`)
  so defence-in-depth kicks in at the DB layer.
